# 业务解决方案

## 一句话定位
面向床垫选购人群的微信小程序导购工具：用专业内容种草 + 可分享的选品单沉淀决策，帮用户在多个候选床垫间横向比较，最终通过微信私域/内容引流完成购买转化（交易端在 V1.1 范围外）。

## 目标用户与核心任务
| 用户角色 | 核心任务 |
|---------|---------|
| 床垫选购者（新房装修/换床垫） | 按材质/软硬/尺寸筛选床垫、阅读种草内容、把心仪的床垫加入多个备选清单 |
| 被分享的好友（接盘推荐） | 打开小程序卡片/海报直接看到分享者的选品单内容 |
| 运营人员（Admin） | 上架/下架商品、维护分类标签、发布文章视频并挂商品链接 |
| Designer | 在 Figma 产出 UI 稿（外部角色，见 docs/design/figma-handoff.md） |

## 问题 → 能力 → 价值
| 痛点 | 能力 | 价值 |
|------|------|------|
| 床垫参数复杂（材质/软硬/厚度），无从比较 | 核心参数卡片 + 瀑布流 Feed 展示 | 30 秒建立横向比较维度 |
| 决策周期长，几个候选拿不定 | 多选品单（主卧备选/次卧备选） | 结构化沉淀决策过程 |
| 要分享给家人朋友商量 | 小程序卡片 + 小程序码分享，scene 直开清单 | 决策链路微信内闭环 |
| 不知道买什么、需要内容种草 | 图文/视频内容 Feed + 底部关联商品带货 | 内容 → 商品转化 |
| 单品多、找货难 | 分类 + 搜索（材质词/尺寸词/品牌词） | 快速定位 |

## 核心业务流程
1. 运营在 Admin 发布商品SPU/SKU、维护分类标签；发布文章/视频并挂载关联商品
2. 用户打开小程序：首页 Feed/分类/搜索 → 商品详情 → 「加入选品单」
3. 用户新建/管理多个选品单；在选品单详情点分享 → 生成带 scene=清单ID 的小程序码海报 或 转发小程序卡片
4. 好友点击卡片/扫码 → 小程序 onLoad 解析 scene → 直接展示分享者的选品单
5. 用户阅读内容 Feed → 图文/视频详情 → 底部关联商品 → 同样可加入选品单

## 能力边界
- V1.1 无订单/支付/购物车：交易转化走微信私域/外部渠道，小程序不做收款
- 搜索为 MySQL 模糊/全文，不承诺搜索引擎级相关排序
- 无多商户/分销/会员体系
- 分享数据回显为只读视图（好友可看清单但不可编辑分享者的清单）
- 商品主图/视频为运营上传素材，无自动清洗

## 待补充（用户/Designer 确认）
- Banner/金刚区运营位数量与配置入口（Admin 端是否要可视化配置）
- 商品视频与内容视频的存储方式（云存储厂商未定，腾讯云 COS 先作为默认）
- 选品单是否需要「公开/私密」开关（被分享者默认只见内容不能编辑）
