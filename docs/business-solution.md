# 业务解决方案（V2.0）

## 一句话定位
面向 **B 端导购/经销商**的床垫销售赋能微信小程序：产品数字化展示（替代纸质手册）+ 客户定制方案快速生成 + 方案微信一键分享，品牌与服务体系随方案传递。明确不做 C 端下单/支付/物流/会员（aaa.md §1.2）。

## 目标用户与核心任务
| 用户角色 | 端 | 核心任务 |
|---------|----|---------|
| 门店导购 | 微信小程序 | 为单个客户快速生成床垫选品方案，微信分享给客户确认 |
| 经销商业务员 | 微信小程序 | 外出拜访时展示产品库，现场制作方案 |
| 品牌运营人员 | Web 管理后台 | 维护产品信息、轮播图、资讯内容、品牌信息 |
| 内容管理员 | Web 管理后台 | 审核方案数据、查看运营统计 |
| Designer | — | 产出 UI 稿（参考图见 `jp/`，见 docs/design/figma-handoff.md） |

## 问题 → 能力 → 价值
| 痛点 | 能力 | 价值 |
|------|------|------|
| 纸质手册更新慢、信息不全 | 产品数字化展示（参数/详情/实拍图） | 随时最新产品库 |
| 客户需求各异，口头介绍低效 | 多方案管理（一客户一方案）+ 快照固化 | 30 秒生成定制方案 |
| 方案要发给客户/家人商量 | 微信卡片分享，免登录只读预览 | 决策链路微信内闭环 |
| 产品更新后历史方案混乱 | 方案快照机制（JSON 固化） | 历史方案永远保持创建时状态 |
| 品牌价值传递靠嘴 | 品牌介绍/客服承诺/招商加盟位 | 品牌随方案传递 |

## 核心业务流程
1. 运营在 Admin 维护产品（7 大分类）、轮播图、资讯与服务、品牌信息
2. 导购打开小程序：首页/分类/搜索 → 产品详情 → 悬浮「选款」加入选品（Pinia）
3. 底部已选栏点 OK → 方案编辑页（标题/备注/产品管理）→ 保存（生成快照）→ 预览分享
4. 客户点分享卡片 → 免登录只读预览（/schemes/{id}/public）
5. 分享计数 +1；Admin 可看方案数据与运营统计

## 能力边界
- 无订单/支付/购物车/会员：转化在线下成交，小程序不做收款
- 搜索为 MySQL 模糊/全文，不承诺搜索引擎级相关排序
- 方案公开预览为只读，访客无编辑/删除入口
- 商品主图/实拍图/视频为运营上传素材
