# 待确认问题存档

> **用途**：开发按现有设计稿推进，本清单中的疑问**不阻塞开发**，先按稿实现，完成后统一优化。
> **来源**：`design-spec/spec.md` §7，共 13 条。
> **更新方式**：每条问题的状态在「状态」列更新，解决后补「决议」说明，不改原始描述（保留追溯）。

## 状态说明

| 状态 | 含义 |
|---|---|
| `PENDING` | 待确认，按稿实现 |
| `DEFERRED` | 已决定本轮不做，留待优化 |
| `DECIDED` | 已确认，决议见备注 |
| `BLOCKED` | 无法按稿实现，必须中断等确认（本清单**当前无此类**） |

## 一、结构与入口（会影响导航骨架，但先按稿实现）

### Q1 · 底部 Tab 两套结构不统一

- **状态**：`DEFERRED` → 优化阶段处理
- **现象**：
  - 首页 `86:1233` / 产品分类列表 `86:1144` / 我的 `86:539` → 三项版 `首页 · 产品 · 我的`
  - 产品页 `86:1027` / 产品详情页 `86:951` → 两项版 `首页 · 返回`（`icon/home` + `undo-2`）
- **当前实现方案**：严格照稿。三项页用三项 TabBar，两项页用两项 TabBar。
- **优化方向**：详情类页面应统一为「顶部返回 + 三项 TabBar」，去掉底部「返回」项（该页顶部导航左侧已有 `chevron-left` 22×22，功能重复）。
- **风险**：两项版 TabBar 只有 2 个 item，`justify-between` 在两个窄屏设备上视觉会散，需在实现时确认布局表现。

### Q2 · 「我的」页没有方案入口

- **状态**：`DEFERRED`
- **现象**：方案列表 `86:662` 只能从方案编辑页的「我的方案」按钮进入。用户从首页出发，走「我的」Tab 无法找到已保存的方案。
- **当前实现方案**：照稿，不加任何入口。
- **优化方向**：在「我的」页品牌卡下方或客服卡上方，增加「我的方案」模块（列表 / 入口卡）。

### Q3 · 方案编辑页三个并列按钮无主次

- **状态**：`DEFERRED`
- **位置**：方案选择1 `86:901` / 方案选择3 `86:707` 底部操作条（`bg navy` `p14` `gap8`）
- **现象**：`我的方案`(108×42 白底描边) / `保存`(92×42 yellow) / `预览分享`(119×42 yellow)，两个黄色主按钮并列，视觉权重相同。
- **当前实现方案**：照稿，三个按钮等权重实现。
- **优化方向**：`保存` 保留主按钮；`预览分享` 降为次按钮（白底描边）；`我的方案` 提到顶部导航或改为文字链。

## 二、信息缺失（不影响渲染，但影响业务完整性）

### Q4 · 价格信息全流程缺失

- **状态**：`DEFERRED`
- **现象**：产品页列表卡（167×246）、产品详情页、分享卡（`86:603`）均无价格位。
- **当前实现方案**：不实现价格组件，数据层预留位置但不渲染。
- **优化方向**：需先确认业务模式 —— B 端/线下询价（无需展示价格）还是 C 端零售（需补价格）。若需补，列表卡与详情页都要加价格组件（含促销价/划线价/起售价三种形态）。

### Q5 · 产品页排序规则未定义

- **状态**：`DEFERRED`
- **位置**：产品页 `86:1027` 排序行（`综合`选中 / `推荐` / `新品`），h38 `gap34`
- **现象**：三个排序项只有选中视觉（Bold 14px navy + 28×3 指示条），没有排序逻辑定义。
- **当前实现方案**：实现切换交互与选中态，排序字段留空（接口返回顺序）。
- **优化方向**：明确 `综合`（默认权重）/ `推荐`（算法或人工）/ `新品`（上架时间倒序）的字段。

### Q6 · 产品页视图切换目标样式缺失

- **状态**：`DEFERRED`
- **位置**：产品页 `86:1027` 搜索框右侧 `list` 图标 22×22
- **现象**：有切换图标，但无列表视图画板。当前只有 2 列网格（`gap9`，卡 167×246）。
- **当前实现方案**：保留图标可点，切换后仍是网格（或先置灰）。
- **优化方向**：补列表视图设计稿（横向卡：图左文右）。

### Q7 · 链路断点：4 个页面无画板

- **状态**：`DEFERRED`
- **缺失页面**：
  1. 搜索结果页（产品页 / 选品页搜索后）
  2. 品牌介绍页（「我的」→ `了解乐卡思`）
  3. 客服会话页（首页 `联系客服` / 我的页三列服务项）
  4. 文章列表页（首页 `乐卡思资讯`）
- **当前实现方案**：这些入口点击后给 `toast` 提示「功能开发中」或不响应，不自行补设计。
- **优化方向**：补 4 个页面的设计稿，或明确复用微信原生能力（如客服直接用 `button open-type="contact"`）。

## 四、数据与一致性（实现时按稿，但需标记）

- **状态**：`DEFERRED`
- **清单**：
  | 项 | 当前值 | 说明 |

  | 产品页 8 个产品名 | `3D床垫` / `幸福1号` / `幸福2号` / `幸福3号` / `幸福99床垫` / `505压缩卷包床垫` / `323特制版床垫` / `9M 卷绵特制床垫` | 临时名 |

- **优化方向**：接真实商品接口后替换。

### Q10 · 选品页画板宽 381px（异常）

- **状态**：`DEFERRED`
- **现象**：`86:767` 宽 381px，其余 9 个画板均 375px。多出的 6px 导致左右双栏布局（分类栏 94 + 产品区）总宽超屏。
- **当前实现方案**：按 375px 实现，产品区宽度自适应（`flex-1`），不硬编码 126.92px 卡宽，改为按容器宽度计算。
- **优化方向**：核对 Figma 画板是否误操作，统一回 375px。

### Q11 · 选品页产品卡字号为非整数

- **状态**：`DEFERRED`
- **现象**：`86:767` 右栏产品卡（宽 126.92px）内，产品名 **9.88px**、规格 **7.6px**、睡感标签 **8.36px**、详情标签 **7.6px**、操作圆钮 **21.28px**、圆角 **8.36px / 3.04px / 10.64px**。全部是等比缩放的中间结果。
- **当前实现方案**：取整实现 —— 产品名 `10px`、规格 `8px`、睡感标签 `8px`、详情标签 `8px`、操作圆钮 `21px`、圆角 `8px / 3px / 11px`。
- **需确认**：取整后的视觉差异是否可接受（<0.5px，肉眼基本不可辨）。
- **优化方向**：若后续调整卡宽，字号应重新按比例计算而非沿用。

### Q12 · 版本标识条混入正式画板

- **状态**：`DECIDED` → **不实现**
- **现象**：`V3 · 参考复刻优化版` 灰蓝色标识条（h24，`bg #e7eaf6`，文字 10px `#1a2260`）出现在全部 10 个画板，位于微信导航下方。
- **决议**：内部评审标记，**不实现**。已在 `for-developer.md` 与 `spec.md` §8 明确列为不做项。
- **优化方向**：建议设计侧统一从画板移除，或转为 Figma 图层注释。

- **状态**：`DEFERRED`

## 六、用户 2026-11-14 决策补充（V3 落地启动）

### Q14 · 首页轮播 vs spec §8 不做清单冲突

- **状态**：`DECIDED` → **保留轮播**
- **冲突**：`spec.md §5.1` 在品牌主视觉卡内画了 4 个轮播指示点，但 `spec.md §8` 不做清单写明「不实现首页轮播自动播放逻辑（画板仅示意 4 个指示点位置）」。
- **决议（用户 2026-11-14）**：首页**保留轮播**，数据接 `GET /wxapi/home` 的 banners，autoplay 5s，指示点数量随 banners.length 动态；仅 1 张时隐藏指示点。
- **影响**：`spec.md §8` 该条作废（其余不做清单条目仍有效）。后端 `gin_banner` 表 + Admin 轮播图管理（BE-08）继续保留并在小程序端消费。

### Q15 · 分类数量：稿内 7 个 vs 定稿 8 个

- **状态**：`DECIDED` → **8 个分类**
- **现象**：`spec.md §5.2` 分类列表页只列 7 项；首页还有 3 个寝具入口（9B/9D/9P）未归入分类。
- **决议（用户 2026-11-14）**：
  1. 分类共 **8 个**，顺序即 sort：6S专属床垫 / 手工 · 零胶虑 / 姜大师 · 草本 / 双面控 / 零压 · 深睡 / “卷”起来 / 次卧 · 不次等 / 薄垫 · 不薄待。
  2. 每个分类**同时提供文字与图片两套内容**，接口都返回：`name`（标题文字）+ `subtitle`（副文案文字）+ `banner_image`（标题+文案做成的整块图片 URL）。
  3. **渲染规则：`banner_image` 非空时优先显示图片；为空时降级显示 `name` + `subtitle` 文字。** 本轮 seed 的 `banner_image` 全部为 null，走文字路径；设计侧出图后由 Admin 上传即可切换，前端不改代码。
  4. **寝具 3 入口不是分类**：点击 → 产品页并按型号搜索（keyword = 9B / 9D / 9P），不新建分类。
- **待同步**：`spec.md §5.2` 的 7 项清单需更新为 8 项（含「次卧 · 不次等」），由设计侧修订；实现以本条为准。

## 开发推进原则

1. **按稿实现**，不为任何 `DEFERRED` 问题自行补设计。
2. **数据层预留**：Q4 价格、Q5 排序、Q9 真实数据 —— 字段结构留全，先渲染稿件内容。
3. **组件留口**：Q1 TabBar 两套结构做成同一组件的 `variant`；Q3 按钮主次做成可配的 `variant`，优化阶段只改配置不改结构。
4. **热区先行**：Q13 在实现时就扩大透明热区，不等到优化阶段（这是无障碍基线，不是可选项）。
5. **Q12 直接跳过**，不写版本条。
